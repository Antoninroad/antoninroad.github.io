Les mods de Claude Code : ton interface, tes garde-fous

Depuis la 2.1.287, un mod peut dessiner un panneau, arrêter une commande dangereuse et remplacer ce que Claude Code affiche. Ce qu’ils font vraiment, et le piège à connaître avant d’en installer un.

Ce que c’est

Le 1er octobre 2026, Claude Code a appris à charger des mods (version 2.1.287). Un mod est un plugin : un dossier avec un manifeste, un hooks.json et un fichier JavaScript ou TypeScript. Claude Code appelle ses fonctions quand un événement arrive, par exemple un appel d’outil, un prompt envoyé ou une partie de l’interface qui se dessine.

La fonction peut alors observer, modifier ou prendre la main sur cet événement.

Ça ressemble aux hooks de réglages, avec une différence de taille : un hook de réglages lance un script ou une requête HTTP depuis l’extérieur, alors qu’un mod tourne à l’intérieur de Claude Code. C’est ce qui lui permet de dessiner.

Ce qu’un mod peut faire

  1. Dessiner dans l’interface : un panneau à côté de la conversation, une bande au-dessus du prompt, avec des boutons, des onglets et des champs. Il peut aussi redessiner ce que Claude Code dessine lui-même, comme la ligne d’un appel d’outil, le spinner ou le dialogue des questions.
  2. Retenir un appel d’outil : l’exemple officiel blast-radius attrape une commande risquée comme rm -rf ou un git push --force, montre ce qu’elle changerait, puis propose deux boutons : continuer ou annuler.
  3. Transformer une idée en interface : tu décris ce que tu veux dans une session, Claude écrit le mod, tu le charges. Anthropic partage trois exemples complets : token-weather (la météo de ton contexte au-dessus du prompt), blast-radius et replay-theater (une commande /replay qui rejoue les dernières modifications).

Un mod peut aussi ajouter une commande / qui lance ton code tout de suite, sans passer par un tour de Claude.

Où ça marche

  • Dans le terminal, avec Claude Code 2.1.287 ou plus.
  • Dans l’onglet Code de l’appli Desktop, avec 2.1.286 ou plus.
  • Dans l’extension VS Code, mais le dessin demande la version 2.1.299 ou plus.
  • En claude -p et dans l’Agent SDK, les hooks tournent mais rien ne s’affiche.
  • Dans une session WSL de l’appli Desktop, les plugins ne sont pas disponibles du tout.

Le piège

Un mod n’est pas sandboxé. Il tourne avec tes permissions, et une fois chargé il peut :

  • lire et écrire tes fichiers, lancer des programmes, faire des requêtes réseau ;
  • lire tes secrets, donc tes variables d’environnement et tes fichiers de réglages, y compris une clé API ;
  • voir chaque prompt et chaque appel d’outil ;
  • approuver un appel à ta place, ou envoyer un message depuis une autre de tes sessions ;
  • consommer ton forfait en appelant un modèle.

La sandbox de Claude Code protège les commandes Bash. Un processus lancé par un mod tourne en dehors.

Deux limites honnêtes : un mod ne peut pas modifier l’écran de demande de permission, et il ne peut pas changer ce que cet écran t’affiche.

Vérifier et couper

Avant d’installer, tu peux lister ce qu’un mod fait sans l’exécuter. Récupère ses fichiers, puis lance claude plugin validate ./le-mod : les lignes hooks: et calls: disent quels événements il écoute et ce qu’il demande (fichiers, réseau, processus).

Pour le couper :

  • un seul mod : l’onglet Installed de /plugin ;
  • tous les mods pour une session : lancer Claude Code avec --safe-mode ;
  • tous les mods que tu as installés, partout : "disableAllHooks": true dans ~/.claude/settings.json. Attention, ça coupe aussi tes hooks de réglages et ta ligne de statut.

Mes 3 conseils

Ce sont mes conseils, pas ceux d’Anthropic.

  1. Commence par les exemples officiels. Charge-les pour une seule session avec --plugin-dir : tu lis le code avant de l’exécuter, et rien n’est installé.
  2. Lis les calls: avant d’installer. Un mod qui demande le réseau et la lecture de tes fichiers pour afficher une jauge de contexte, c’est un mauvais signe. Installe seulement ce que tu as lu.
  3. Écris le tien. Quelques dizaines de lignes suffisent pour un panneau. C’est du code que tu peux relire, et tu n’as personne d’autre à croire sur parole.

Ce qui marche encore mal

  • Le dessin ne suit pas partout : rien en claude -p, rien dans l’Agent SDK, rien en WSL.
  • L’extension VS Code a besoin de la 2.1.299 pour afficher ce qu’un mod dessine.
  • Un mod ne peut pas toucher à l’écran de permission, volontairement.
  • Les exemples d’Anthropic sont fournis tels quels, sans support.

Tu es en France ?

Oui, les mods marchent ici : ils sont activés par défaut, sans restriction de pays, avec un abonnement Claude ou une clé API, y compris en passant par Bedrock, Vertex ou Foundry. Le seul vrai frein, c’est la version de Claude Code : 2.1.287 en terminal, 2.1.286 dans l’appli Desktop.
